# 汉文化知识图谱

以 **Neo4j 图数据库**为核心、**Flask + ECharts** 为可视化的汉文化知识图谱项目。
围绕「人物 — 朝代 — 著作 — 地点」四类实体，构建关系网络，并提供图谱可视化、路径查询、相似人物推荐与智能问答。

## 四、快速开始

### 1. 启动 Neo4j 数据库
cd E:\neo\neo4j-community-2025.02.0\bin
neo4j console

前端的数据全部来自 Neo4j，**必须先启动数据库**，否则页面顶部会提示「数据库连接异常」。

- **Neo4j Desktop**：打开对应项目，点击 Start。
- **解压版 / 安装版**：以管理员身份打开命令提示符，进入 Neo4j 的 `bin` 目录，执行：

  ```bat
  neo4j.bat console
  ```

  看到 `Started.` 字样后，浏览器打开 <http://localhost:7474> 能进入 Neo4j Browser，即表示数据库已就绪。

### 2. 环境要求

- Python 3.10 及以上（本项目在 Python 3.12.4 上验证）
- Neo4j 4.x / 5.x，已启动并可通过 `bolt://localhost:7687` 访问
- 系统中若存在多个 Python（例如 MSYS2、Anaconda 各带一个），建议统一使用 Windows 官方启动器 `py -3`

### 3. 安装依赖

**方式一：一键脚本（推荐）**

双击项目根目录的 **`启动前端.bat`**，脚本会自动创建虚拟环境、安装依赖并启动服务。

**方式二：手动安装**

在 `03_图谱前端` 目录下执行：

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r ..\requirements.txt
```

习惯使用 **Anaconda Prompt** 的，直接在 Anaconda Prompt 中执行上面两条命令即可。

### 4. 配置数据库连接

打开 `03_图谱前端/neo4j_db.py`，按自己的环境修改开头三行：

```python
NEO4J_URI = "bolt://localhost:7687"
NEO4J_USER = "neo4j"
NEO4J_PASSWORD = "12345678"   # ← 改成你的密码
```

### 5. 启动服务

```bat
cd 03_图谱前端
.venv\Scripts\python.exe app.py
```

也可以直接用一键脚本启动。

看到以下输出即启动成功：

```
🏛️ 汉文化知识图谱 Web 应用
📍 访问地址: http://localhost:5000
```

用浏览器打开 <http://127.0.0.1:5000> 即可。

> 若数据库中没有数据，可先运行 `02_数据处理/三元组/task4_import_to_neo4j.py` 导入三元组。

| 功能 | 说明 |

## 七、常见问题

**页面顶部出现「数据库连接异常」**
Neo4j 未启动，或 `neo4j_db.py` 中的账号密码不正确。先用 Neo4j Browser 确认能连上再刷新页面。

**端口 5000 被占用**
修改 `app.py` 最后一行的 `port=5000` 为其他端口（如 5001）。

**页面空白 / 图表不显示**
本项目已把 ECharts 放在本地（`static/vendor/echarts.min.js`），断网也能正常打开；若该文件缺失，页面会自动回退到 CDN，此时需要网络。

**修改了前端代码但页面没变化**
浏览器缓存所致，按 `Ctrl + F5` 强制刷新。

**提示「创建虚拟环境失败」或「未找到可用的 Python」**
系统中若存在多个 Python（例如 MSYS2 自带的 `python`），PATH 里靠前的那个可能无法创建虚拟环境。
一键脚本已优先调用官方启动器 `py -3`；手动操作时也建议：

```bat
py -3 -m venv .venv
```

**双击 `启动前端.bat` 后窗口一闪而过**
批处理文件必须使用 Windows 原生格式保存（**GBK 编码 + CRLF 行尾**）。本项目提供的脚本已处理好；
若你自行用文本编辑器修改过，请勿另存为 UTF-8 编码或 LF 行尾。

**启动后提示 `Address already in use`**
5000 端口已被占用（例如上一次的服务窗口还没关闭）。关闭旧窗口后重试，或修改 `app.py` 最后一行的端口号。

## 八、开发记录

### 前端重构（本次）

原前端把 30 个节点的坐标和类型全部硬编码在 `index.html` 中，存在两个实际问题：

1. **节点丢失**：数据库中朝代名称为「唐」「宋」「汉」，而页面硬编码的是「唐朝」「宋朝」「汉朝」，名称不匹配导致这 3 个朝代节点及其关联连线完全不显示（实际只渲染出 27 个）。
2. **无法扩展**：一旦新增任何节点，由于没有对应坐标，页面会直接跳过该节点。

重构后的方案：

- 新增后端接口 `GET /api/graph`，由数据库一次性返回节点（含类型与度数）与关系，页面不再硬编码任何数据；
- 改用 ECharts 力导向布局，节点大小按关联度自适应（30 个节点全部显示）；
- 样式拆分为独立 CSS，交互逻辑拆分为独立 JS，移除 jQuery 依赖；
- ECharts 本地化，断网可用；
- 新增分类过滤、邻域聚焦、路径高亮、导出 PNG、加载与错误提示、窄屏适配等能力。

重构后经无头浏览器逐项交互验证，18 项功能测试全部通过，原有接口全部保持向后兼容。

### 健壮性改进

- **延迟连接数据库**：`neo4j_db.py` 原先在模块导入阶段就建立连接，Neo4j 未启动时整个 Web 应用会直接崩溃、连页面都打不开。
  现改为首次真正执行查询时才连接，数据库没开也能正常启动服务，页面顶部给出明确提示；
- **友好的错误提示**：`app.py` 捕获数据库连接异常并返回 `503` 与中文说明，页面告警条不再直接显示原始英文报错；
- **启动脚本**：使用 GBK 编码 + CRLF 行尾（Windows 批处理的原生要求），并优先通过 `py -3` 创建虚拟环境，
  避免 PATH 中不受支持的 Python 解释器（例如 MSYS2 自带的 `python`）导致创建失败。
